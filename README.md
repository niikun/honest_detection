# honest_detection

違反の通報に、どんな報酬を付けると、集団の違反が減るか。それを確かめる小さなシミュレーションです（Rust 製）。

N 人（既定は 10 人）が毎ラウンド「守る / 違反する」を選び、他人の違反を見た人は「通報する / 無視する」を選びます。全員が独立に Q 学習（ε-greedy）で、得な行動を覚えます。**通報者への報われ方だけを変えて**、違反率がどう変わるかを比べます。

学習用に一から書いているプロジェクトで、台帳・評判・API は作成中です。

## 3つの条件

| 条件 | 通報者に起きること | 違反者に起きること |
|---|---|---|
| `none` | 手間（コスト）だけかかる | 罰なし |
| `immediate` | 通報の瞬間に報酬がもらえる。真偽は確かめない | 罰なし |
| `retro` | 通報の瞬間の報酬に加え、後で照合する。本物ならボーナス、偽物なら罰 | 本物の通報で確定したときだけ罰（通報者が何人でも1回） |

## 結果

3000 ラウンド × 20 シード、末尾 20% の平均です（N = 10）。

| 条件 | 違反率 | 偽通報 /人/ラウンド | 総損害 /ラウンド |
|---|---|---|---|
| none | 0.976 | 0.012 | 26.34 |
| immediate | 0.976 | 0.498 | 26.34 |
| retro | **0.033** | 0.023 | **0.89** |

- `none` と `immediate` は違反が減りません。`immediate` は、真偽を確かめないので偽通報だけが増えます。
- 違反が減るのは `retro` だけです。罰が付くのは、後の照合で本物と確定した通報だけだからです。
- 偽通報の絶対値は、「各自が 1 ラウンドに 1 人だけ見る」仕組みなので、他のモデルとは比べられません。条件どうしの向きと倍率で比べてください。

## 使い方

```sh
cargo run      # 3 条件 × 20 シードの表を表示する
cargo test     # テスト
```

Rust 2024 edition が必要です。乱数は `rand` 0.10 を使い、シードを固定しているので、結果は再現できます。

## 台帳（作成中）

起きた出来事を、1 件ずつ末尾に足していく記録です。書いた行は消さず、書き換えない方針です。

### イベント

1 本の `Vec<Event>` に、次の 3 種類を時系列で並べます。

| 種類 | 持つ情報 | 意味 |
|---|---|---|
| `Report` | 誰が・誰を | 通報（主張） |
| `Judge` | 誰が・誰を・本物か | 照合の結果（確定） |
| `Reward` | 誰に・額 | 報酬と罰（結果。罰は負の額） |

どのイベントも `round`（何ラウンド目か）を持ちます。シミュレーションの「誰が違反したか」は台帳に書きません（書くと通報の仕組みが要らなくなるため）。

並びは、通報 1 件ごとに `Report` の直後に `Judge` が来ます。1 つの違反者を複数人が通報しても、罰の `Reward` は 1 件だけです。`none` と `immediate` では罰を書かず、`retro` だけが罰を書きます。

### 照合

通報が本物かどうかを確かめる手順は `Verify` トレイトに切り出しています。

- `verify(&Event) -> Option<bool>`: `Report` 以外のイベントなら `None`、`Report` なら本物かどうかを返します。
- 今はシミュレーション用の実装（`SimVerifier`）だけです。見た本人の観測（`Observes`）を見て答えます。台帳は `Verify` だけを知っているので、後で別の検証に差し替えられる形です。
- 「見ていない通報は、たまたま当たっても偽物」として扱います。
